# Accessibility

lab.meteo@uniparthenope targets WCAG 2.1 level AA, the level required by EN 301 549 and, in Italy, by Law 4/2004
and the AgID guidelines. The public statement is served at `/accessibility`. Its feedback channel defaults to
`meteo@uniparthenope.it` and the University accessibility page
(https://www.uniparthenope.it/Portale-Ateneo/accessibilita); override it with
`WXHUB_ACCESSIBILITY_CONTACT`.

## Implemented measures

| WCAG criterion | Implementation |
|---|---|
| 1.3.1 Info and relationships | Landmarks (`nav`, `main`, `footer`), table captions and header scopes, fieldsets and legends |
| 1.4.1 Use of colour | Status text and ✓/✗ symbols accompany coloured indicators |
| 1.4.3 Contrast (minimum) | Light-mode links use the primary colour (#1f4e79) (8.7:1) instead of the 3.3:1 secondary blue; dark-mode links use #7cc0ff; muted text is at least 4.5:1 |
| 1.4.10 Reflow | Responsive layouts without horizontal scrolling at 320 CSS pixels on Hub pages and the gallery |
| 2.1.1 Keyboard | Native links, buttons, and form controls only; no keyboard traps |
| 2.4.1 Bypass blocks | "Skip to main content" link on every Hub page and on the gallery |
| 2.4.7 Focus visible | 3 px focus ring on all interactive elements |
| 3.3.1, 3.3.2 Errors and labels | Visible labels; login errors are announced and linked with `aria-describedby` |
| 4.1.2 Name, role, value | Toggle buttons expose `aria-pressed`; icon-only controls have accessible names |
| 2.3.3 / user preferences | `prefers-reduced-motion`, `prefers-color-scheme`, and forced-colours support |

## Known limitations

- JupyterLab and JupyterLite are third-party applications; some interactions remain difficult with
  screen readers, a problem documented for data-science notebooks in general (see
  [Design rationale](design-rationale.md), reference 22).
- Figures generated by notebooks have no automatic text alternatives.
- User-authored notebook content is outside the provider's control.

## Checking a change

1. Navigate every changed page with the keyboard alone and confirm the focus order and ring.
2. Check contrast of new colours with a WCAG contrast checker in both themes.
3. Zoom to 400 % (or a 320 px viewport) and confirm content reflows.
4. Run an automated checker (for example axe or WAVE) and review its findings manually.
5. Update the statement in `jupyterhub/templates/wxhub_accessibility.html` if conformance changes.
